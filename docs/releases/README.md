# Releases

As notas de release devem corresponder a tags Git existentes no formato semântico, como `v1.0.0` ou `v1.0.1`. Não publique nota como release nem registre versão/tag antes de ela existir no histórico Git.

Para uma versão publicada, crie um arquivo `vX.Y.Z.md` com resumo e alterações relevantes, usando o changelog como referência. Mantenha links entre nota e tag quando disponíveis.

No momento desta auditoria não há tags Git de versão. A versão `0.1.0` em `package.json` é a versão declarada do pacote e não comprova uma release etiquetada.
